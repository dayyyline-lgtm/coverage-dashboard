# 자동 갱신 트리거 설정 (Cloudflare Worker)

GitHub 자체 예약 스케줄러가 새 저장소에서 잘 안 붙는 문제가 있어,
**Cloudflare Cron Trigger** 가 정해진 시각에 GitHub Actions 를 대신 실행시킵니다.

토큰이 본인 Cloudflare 계정 안에만 저장되므로 외부 서비스에 맡기는 것보다 안전합니다.

---

## 1단계 · GitHub 토큰 준비 (2분)

기존 토큰에 `workflow` 권한이 없으면 새로 만들어야 합니다.

1. <https://github.com/settings/tokens> → **Generate new token (classic)**
2. Note: `cloudflare-cron`
3. Expiration: **No expiration**
4. 체크할 항목 — **`repo`** 와 **`workflow`** 두 개
5. **Generate token** → 나오는 `ghp_...` 복사 (이 화면 벗어나면 다시 못 봅니다)

---

## 2단계 · Worker 만들기 (3분)

1. <https://dash.cloudflare.com> → 왼쪽 **Compute** → **Workers & Pages**
2. **Create** → **Workers** 탭 → **Start with Hello World!** → **Deploy**
   - 이름: `coverage-cron` (아무거나)
3. 배포되면 **Edit code** (또는 `</> Edit Code`) 클릭
4. 편집기 내용을 **전부 지우고**, 옆 폴더의 `worker.js` 내용을 **통째로 붙여넣기**
5. 우측 상단 **Deploy**

---

## 3단계 · 토큰 등록 (1분)

Worker 화면 → **Settings** → **Variables and Secrets** → **Add**

| 항목 | 값 |
|---|---|
| Type | **Secret** |
| Variable name | `GH_TOKEN` |
| Value | 1단계에서 복사한 `ghp_...` |

→ **Deploy** / **Save**

---

## 4단계 · 실행 시각 등록 (2분)

Worker 화면 → **Settings** → **Trigger Events** → **Add** → **Cron Trigger**

> ⚠ **무료 플랜은 Cron Trigger 가 계정당 5개다.** 넘으면 Add 버튼이 그냥 안 눌린다
> (오류 메시지도 안 뜬다 — 2026-08-11 실제로 겪었다). 그래서 **시각마다 하나씩 만들지 않고
> 묶는다.** 이 워커는 cron 문자열이 아니라 **실제 발화 시각**으로 분기하므로 묶어도 정확하다.
> 요일은 **이름**(`SUN-THU`)으로 — Cloudflare 가 숫자(`0-4`)를 거부한다.

아래 5개를 **하나씩** 추가합니다 (모두 UTC 기준, 괄호는 한국시간):

```
0 20,21 * * SUN-THU        (평일 05:00 수집 + 06:00 레터·뉴스봇)   ★
0 22,23 * * SUN-THU        (평일 07,08시 시세)
0 0-9 * * MON-FRI          (평일 09~18시 시세)
0 3,7,11,15,19,23 * * SAT  (토요일 시세)
0 3,7,11 * * SUN           (일요일 시세)
```

★ 이 한 줄이 아침 파이프라인 전부다. 예전엔 `45 20 * * SUN-THU`(05:45 수집만)였는데,
**레터·뉴스봇을 부르는 21시 슬롯이 없어서 뉴스봇이 클라우드에서 한 번도 안 돌았다.**
`0 20,21` 로 바꾸면 트리거를 늘리지 않고 둘 다 된다.

---

## 5단계 · 확인

Worker 주소(`https://coverage-cron.<계정>.workers.dev`)를 브라우저로 열고 뒤에 붙이기:

```
?wf=refresh.yml&key=<TRIGGER_KEY>
```

`{"ok": true, "status": 204}` 가 나오면 성공입니다.

> 🔑 **`TRIGGER_KEY` 를 먼저 넣어야 합니다.** `GH_TOKEN` 과 같은 자리
> (Settings > Variables and Secrets)에 Secret 으로 아무 긴 문자열을 넣으세요.
> 키가 없거나 틀리면 **404** 가 뜹니다 — 주소만 아는 사람이 워크플로를 돌리지
> 못하게 막는 장치입니다. 예약 실행(cron)은 이 검사와 무관하게 그대로 돕니다.
GitHub Actions 탭에 새 실행이 뜨는지 확인하세요.

---

## 동작 방식

```
Cloudflare Cron  →  GitHub Actions 실행 요청  →  워크플로 동작
                                                  ↓
                                          시세 수집 → 커밋 → Pages 자동 배포
```

GitHub 예약이 나중에 정상 동작하기 시작해도 문제없습니다.
데이터 변동이 없으면 커밋하지 않으므로 중복 실행돼도 배포가 쌓이지 않습니다.

원치 않으면 `.github/workflows/*.yml` 의 `schedule:` 블록을 지우면
Cloudflare 트리거만 남습니다.

# CGV 좌석 중계 워커 `cgv-relay` (2026-09-28 추가)

GitHub 서버(미국)는 CGV 가 접속을 막아서(403) 극장 좌석 수집에 CGV 가 빠졌다. **Cloudflare 워커를 거치면 열린다**
(러너에서 실측: 직접 403 → 워커 경유 200). 그래서 CGV 요청만 이 워커를 거친다. 위의 `coverage-cron` 과는 **별개 워커**다 —
자동 갱신 트리거를 건드리지 않으려고 따로 만든다.

**비밀값을 넣을 필요가 없다.** 워커가 "우리 저장소의 GitHub 워크플로가 보낸 요청인가"를 GitHub 서명(OIDC)으로 직접 확인한다.
토큰 없거나 다른 곳에서 온 요청은 401, CGV 예매 조회 API 가 아닌 주소는 404 (러너에서 다섯 경우 모두 확인).

## 만드는 법 (3분)

1. <https://dash.cloudflare.com> → 왼쪽 **Compute** → **Workers & Pages**
2. **Create** → **Workers** 탭 → **Start with Hello World!**
3. 이름을 **`cgv-relay`** 로 바꾸고 → **Deploy**   ← 이름이 정확해야 주소가 `https://cgv-relay.dayyyline.workers.dev` 가 된다
4. 배포되면 **Edit code** → 편집기 내용을 **전부 지우고** 이 폴더의 **`cgv-relay.js`** 를 통째로 붙여넣기 → 우측 상단 **Deploy**
5. 설정(시크릿·Cron)은 **아무것도 안 넣는다.**

확인: 브라우저로 <https://cgv-relay.dayyyline.workers.dev/api/v1/booking/searchAtktTopPostrList> 를 열면
`unauthorized` 가 떠야 정상이다(토큰 없는 요청은 거절). `Not found` 나 Cloudflare 오류 화면이면 이름·코드를 다시 볼 것.

수집기 쪽 연결은 이미 되어 있다 — `boxseats.yml` 의 `CGV_RELAY` 환경변수 + `fetch_screens.http_json` 이 cgv.co.kr 요청만 워커로 돌린다.
이 PC(한국 IP)에서 손으로 돌릴 땐 `CGV_RELAY` 가 없으니 예전처럼 직접 부른다.
